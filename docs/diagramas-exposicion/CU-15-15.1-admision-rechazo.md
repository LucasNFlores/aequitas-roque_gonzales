# CU 15 y CU 15.1 — Admisión y rechazo

## Qué representa

Flujo real de admisión y rechazo de un proceso pendiente. CU 15 y CU 15.1 comparten la misma pantalla, el mismo actor y el mismo mecanismo de autorización, por eso se presentan como dos ramas de un mismo diagrama.

## Diagrama

```mermaid
sequenceDiagram
    autonumber
    actor Coordinador as Coordinador / Administrador
    participant Vista as Vista procesos.index
    participant Componente as Procesos.Index (Livewire)
    participant Policy as ProcesoPolicy
    participant Accion as AdmitirProceso / RechazarProceso
    participant DB as Transaccion DB
    participant Proceso as Proceso (Model)

    alt Admisión
        Coordinador->>Vista: Clic en "Admitir"
        Vista->>Componente: admitProcess(procesoId)
        Componente->>Componente: authorizedProcess(procesoId, 'admit')
        Componente->>Componente: findVisibleProceso() + Proceso::visibleTo(user)
        Componente->>Policy: authorize('admit', proceso)
        Policy-->>Componente: can('admitir_procesos')
        Componente->>Accion: AdmitirProceso::handle(proceso)
        Accion->>DB: transaction
        Accion->>Proceso: lockForUpdate()->findOrFail(id)
        alt Proceso no está pendiente

            alt Estado no activo

                Componente-->>Vista: addError('admission', mensaje)
            else Estado activo
                Accion->>Proceso: forceFill(motivo_rechazo = null)
                Accion->>Proceso: transitionTo(estado, 'Admisión aprobada.')
                Proceso->>Proceso: valida estado activo/no eliminado y guarda
                Proceso->>Historial: evento updated -> recordStateChange(...)

                Proceso-->>Accion: OK
                Accion-->>Componente: OK

            end
        end
    else Rechazo
        Coordinador->>Vista: Clic en "Rechazar"
        Vista->>Componente: prepareRejection(procesoId)
        Componente->>Componente: authorizedProcess(procesoId, 'reject')
        Componente->>Policy: authorize('reject', proceso)
        Policy-->>Componente: can('registrar_motivo_rechazo')
        Componente->>Componente: verifica estado pendiente
        Note over Componente,Vista: Si no está pendiente, corta con error antes del modal.
        Componente-->>Vista: showRejectionModal = true
        Coordinador->>Vista: motivo de rechazo
        Vista->>Componente: saveRejection()

        Componente->>Policy: authorize('reject', proceso)
        Componente->>Componente: trim(motivo) + validate(required|max:5000)
        alt Motivo vacío o inválido
            Componente-->>Vista: error motivoRechazo
            Note over Componente,Vista: El flujo termina sin llamar a la Action
        else Motivo válido
            Componente->>Accion: RechazarProceso::handle(proceso, motivo)
            Accion->>DB: transaction
            Accion->>Proceso: lockForUpdate()->findOrFail(id)
            alt Proceso no está pendiente
                Accion-->>Componente: DomainException
                Componente-->>Vista: addError('motivoRechazo', mensaje)
            else Proceso pendiente
                Accion->>Estado: active()->where('slug', 'rechazado')->first()
                alt Estado no activo
                    Accion-->>Componente: DomainException
                    Componente-->>Vista: addError('motivoRechazo', mensaje)
                else Estado activo
                    Accion->>Proceso: forceFill(motivo_rechazo = motivo)
                    Accion->>Proceso: transitionTo(estado, motivo)
                    Proceso->>Proceso: valida estado activo/no eliminado y guarda
                    Proceso->>Historial: evento updated -> recordStateChange(...)
                    Historial-->>Proceso: historial creado
                    Proceso-->>Accion: OK
                    Accion-->>Componente: OK
                    Componente->>Componente: finishProcessAction('Proceso rechazado...')
                    Componente-->>Vista: successMessage + dispatch('proceso-estado-actualizado')
                end
            end
        end
    end

    Note over Accion,Historial: El historial guarda estado anterior, estado nuevo, motivo, usuario y fecha.
    Note over Componente,Historial: Este flujo no crea Notificacion.
```

## Cómo explicarlo

1. El Coordinador o Administrador elige un proceso pendiente en la bandeja.
2. La autorización se resuelve con `ProcesoPolicy`: `admitir_procesos` para admisión y `registrar_motivo_rechazo` para rechazo.
3. La Action correspondiente abre una transacción y bloquea el proceso para que no se modifique en paralelo.
4. Solo se puede admitir o rechazar si el proceso sigue en estado `pendiente`.
5. El estado destino se busca en `EstadoProceso` y debe estar activo.
6. En el rechazo, el motivo se recorta con `trim()`, es obligatorio y se guarda en el proceso y en el historial.
7. `transitionTo()` guarda el nuevo estado; el evento `updated` del modelo crea el historial con el usuario autenticado.

## Ramas de error representadas

- Proceso que ya no está pendiente: la Action lanza `DomainException`.
- Estado destino inactivo o inexistente: la Action lanza `DomainException`.
- Rechazo sin motivo o con más de 5000 caracteres: error de validación en Livewire.
- Usuario sin permiso: `Gate::authorize()` deniega la operación.

## Diferencia con el diagrama anterior

El diagrama previo mostraba una `Notificacion` al admitir o rechazar. El código actual no la crea. También mostraba `transitionTo('admitido', ...)` con un string; la implementación real recibe un objeto `EstadoProceso`.
